# 用 Agent 做电子取证题：一步一步做到答案可核对

> 最简单的分工：你告诉 Agent 题目在问什么、手上有什么检材；Agent 帮你想“先看哪里、怎么提取、如何计算”；你回到原始检材核对，再提交答案。

## 先记住这 5 件事

1. **先看题目，再找证据。** 不要把整块镜像扔给 Agent 说“帮我做完”。先圈出题目中的人、设备、文件、动作、时间、答案格式。
2. **一次解决一个小问题。** 先找文件，再读字段；先确认数据表，再做统计。每次只给 Agent 当前需要的材料。
3. **告诉它你手上的证据是什么。** 写明检材名称、文件路径、系统类型、时区；如果给的是截图或软件导出表，也要说清楚。
4. **要求它指出证据位置。** 不能只接受一个数字或一句结论；要它说明具体文件、记录、字段、行号、包号或交易哈希。
5. **答案由你复核。** Agent 能帮忙读材料、写查询和解释结果，但它的文字不是证据。最后要能自己回到检材找到依据。

这些题解反复出现的共同做法是：**从题干提关键词 → 找最可能的证据 → 查看原始字段 → 计算或关联 → 回到原始材料复核。**

## 一、先把题目翻译成“要确认什么”

电子取证题常把一句话写得很长。先拆成这些部分：

| 要拆的部分 | 问自己的问题 | 例子 |
|---|---|---|
| 对象 | 在问哪个人、设备、账号、文件或地址？ | 某 Windows 用户；某个钱包地址 |
| 动作/事实 | 想确认什么发生过？ | 登录、安装、发送、删除、访问、转账 |
| 范围 | 题目给了什么时间、设备或数据范围？ | 2025-05-01 到 2025-05-03；仅限手机检材 |
| 口径 | “次数”“金额”“最后一次”具体怎么算？ | 事件行数还是不同账号数；交易还是 Transfer 日志 |
| 格式 | 最后要交什么样的答案？ | 小写包名、UTC+8 时间、整数、保留两位小数 |
| 证据 | 什么材料能直接支持答案？ | EVTX 记录、数据库行、原始邮件头、交易明细 |

### 让 Agent 先拆题，不要马上报答案

```text
我在做一题比赛提供的电子取证练习。请先不要给答案。
把题目拆成：要确认的事实、对象、动作、时间范围/时区、统计口径和答案格式。
然后列出最可能的 3 个证据来源，按优先级说明：去哪里找、要看什么字段、它能证明什么。
缺少材料时先问我缺什么；不要假装看过你实际没有读取的文件。
题目原文：……
检材清单：……
我已经尝试过：……
```

## 二、看题目关键词，决定怎么用 Agent

| 题目里出现这些词 | 通常是什么题 | 你可以让 Agent 做什么 | 最后自己核对什么 |
|---|---|---|---|
| 文件名、创建/修改时间、哈希、簇号、分区 | 文件系统/文件题 | 判断应看文件属性、文件系统元数据还是原始扇区；写哈希或字段读取命令 | 文件路径、分区、字段含义、哈希算法和完整输出 |
| `.eml`、MIME、附件、发件人、Received、SPF/DKIM | 邮件题 | 列出邮件头和附件结构；解释编码、路由记录与认证结果 | 原始邮件头；From 不等于已验证的真实身份；附件需和原邮件对应 |
| IMEI、WhatsApp、应用、账号、聊天、安装时间 | 手机题 | 根据 Android/iOS 类型找应用目录、数据库、备份记录；解释 schema 并写 SQL | 应用是否真的安装/使用；表字段含义；时间单位和时区 |
| IP、端口、扫描、请求、下载、shell、PCAP | 流量题 | 按端点、协议、时间过滤；定位关键流；整理请求/响应 | 包号、流号、源/目的端；扫描不等于成功入侵，TLS 加密时不要编造正文 |
| 登录、账户、工作站、事件日志、网络盘 | Windows 题 | 对导出的 EVTX 表按时间和事件类型筛选；提取账号、IP、工作站等字段 | 记录号、成功/失败、登录类型、SID、时区；单条记录能支持到什么程度 |
| `/etc`、hostname、网卡、Docker、数据库配置、systemd | Linux/服务器题 | 按题目指向查看系统配置、服务配置、历史日志和数据库 schema | 证据来自哪个配置/日志；系统启动或登录仿真是否改变了工作副本 |
| APK、EXE、SO、导出函数、加壳、加密 | 程序分析题 | 先辨认文件类型和结构，再建议静态分析顺序、工具和小脚本 | 不要直接运行未知程序；确认工具输出和代码结论对应同一个文件版本 |
| 多台设备、多个账号、前后关联 | 综合题 | 建立时间线、关联同名账号/地址/文件，标记直接证据和推断 | 时间是否统一；身份是否真的相同；是否有第二个证据来源 |
| 前五名、第三高、总金额、不同用户数 | 表格/数据库统计题 | 帮你定义筛选条件，写 SQL/Python，输出中间表和计算过程 | 是 `COUNT` 还是 `COUNT(DISTINCT ...)`；求和字段、重复行、边界日期和单位 |

## 三、推荐的对话方式：一次只要一种帮助

你可以让 Agent 按三档帮忙，控制它透露多少：

- **提示模式**：我想自己做，只给我一个下一步提示，不要公布答案。
- **带做模式**：告诉我具体操作步骤；每一步等我把结果发回来后，再说下一步。
- **复核模式**：我已经有答案和证据，请找漏洞、口径错误和其他可能解释。

可以直接这样说：

```text
请用提示模式。我想自己做这题。
先只给一条最有帮助的提示，说明我该先看哪类检材，以及为什么；不要给答案。
我做完这一步会把结果贴回来。
```

如果卡住了，不要只说“还是不会”。把你实际做了什么和看到了什么贴回来：

```text
我按你刚才说的打开了……，看到了这些字段/报错：……
我原本以为……，现在不确定……。
请告诉我下一步最小的检查动作，并说明它能排除什么可能。
```

## 四、把证据交给 Agent 时，怎么说清楚

Agent 不一定能访问你电脑上的每个路径。先告诉它你提供的是哪一种材料：

- **文件已上传/在共享工作区中**：说清准确路径，并要求它先确认确实能打开。
- **只有取证软件截图**：说明软件名称、当前页、检材和时区；若题目需要原字段，尽量再导出原始记录。
- **CSV/Excel/SQLite**：先给列名/表名和少量脱敏样例，不要一开始贴整份数据。
- **PCAP/镜像等大文件**：先给文件清单、大小、哈希和你能导出的相关片段；再针对题目决定是否需要进一步分析。
- **无法上传文件**：把错误信息、相关字段和少量上下文贴出来，让 Agent 帮你写下一步查询，而不是让它猜数据内容。

## 五、不同题型的具体问法

### 1. 邮件题：先看原始邮件，不要只看截图

常见问题包括：谁发的、邮件经过哪些服务器、用了什么附件、附件是不是独立传输、邮件客户端是什么。

```text
这是经授权练习中的一封原始 .eml（或完整邮件头）。
请先列出实际存在的字段和值，不要根据显示名称推断身份。
请说明 From、Return-Path、Message-ID、Authentication-Results、SPF/DKIM/ARC 和 Received 各自能支持什么结论、不能支持什么结论。
Received 链请按时间顺序解释，并指出哪些行可能是邮件自带内容、哪些是接收服务器添加。
附件请列出文件名、Content-Type、传输编码、解码后大小和 SHA-256。
每条结论引用原始字段；材料不够时写“无法确认”。
邮件/邮件头：……
```

**Agent 擅长**：解析长邮件头、拆 MIME 附件、写批量提取脚本、把字段讲清楚。

**你要复核**：附件解码后能否正常打开；邮件时间的时区；显示发件人与认证/接收链是否一致。不要只凭一个 From 地址宣布“邮件确实由某人发送”。

### 2. 手机题：搜索不到时，换一个搜索入口

数证杯手机题里，复盘作者遇到过“按题干名字搜不到”的情况，后来转而查看相关应用、包名、缓存图片或应用数据库。这个思路适用于很多手机题：题目里的文字未必原样保存在数据库里。

```text
这道题问：……
检材是：iOS/Android ……；取证工具/导出目录：……
我搜过的词和结果：……
请先给我一个由浅到深的排查顺序：应用列表/包名 → 应用目录 → 数据库表和列 → 附件/缓存 → 相关系统记录。
每一步说清楚要找什么证据、可能的替代解释；暂时不要猜答案。
```

如果找到 SQLite 数据库，先让 Agent 看结构，再查具体字段：

```text
请先解释下面 SQLite 的表名和列名，指出哪些字段可能对应题目中的账号/消息/时间。
然后给一条只读 SQL，保留主键、原始时间值和来源表；解释 WHERE 条件、排序和时间转换。
不要修改数据库。查询结果：……
Schema：……
```

**注意**：应用目录残留不一定代表题目时间内使用过应用；照片里的定位信息可能是拍摄位置而不是拍摄者住址；数据库主文件旁边的 WAL/journal 也可能含有尚未合并的数据。

### 3. Windows 登录题：把“登录”拆成字段

题目问某段时间谁登录、从哪个 IP 登录、哪台工作站发起登录时，Agent 应帮你过滤记录，而不是只报一个 IP。

```text
这题问在……到……期间，Windows 检材上成功登录的来源 IP/工作站。
题目时区：……。我导出的 EVTX CSV 列有：……。
请先给我可复查的筛选条件；把命中的事件 ID、Record ID、时间原值、账户名/SID、登录类型、来源 IP、工作站名列成表。
区分成功与失败；缺字段就标出来。不要只凭一个记录推断是谁实际坐在电脑前。
```

**你要做**：确认日志覆盖了整个时间窗；确认导出工具没有把时间提前/推后；抽查至少一条原始事件。题目要的是“出现过登录记录”时，按该口径统计，不要擅自改成“不同用户数”。

### 4. 流量题：先找关键会话，再读内容

不要逐包从第一行读到最后。先从总体统计缩小范围，再定位关键流。

```text
这是授权练习中的 PCAP。题目问：……
当前已知端点/时间范围：……；我的工具是 Wireshark/tshark/其他……。
请给出由浅到深的过滤顺序：总体统计 → 端点/协议 → 时间 → 可疑会话 → 跟踪流/导出对象。
给出可复制的显示过滤器或命令，并说明命中后应该记录包号、流号、源/目的地址和时间。
不要把端口扫描、失败请求或可疑连接直接说成成功入侵。
```

让 Agent 帮你写 `tshark` 命令时，要求它先说清输入输出字段；运行后把结果贴回，再请它解释。若流量是 TLS 加密，除非有解密材料，否则只能讨论可见的握手/连接信息，不能让 Agent 编造加密正文。

### 5. 表格和数据库统计题：先定口径，再跑计算

2024 数证杯题解包含 Excel 汇总、多表 SQL 和“前几名”统计。最容易错的是数错对象：记录行数、不同账号数、不同交易数和不同彩种数不是一回事。

```text
题目原文：……
数据表/CSV 列名：……；日期字段格式和时区：……。
请先把统计口径写成白话：筛哪些行、按什么字段分组、计数还是求和、是否去重、日期是否含最后一天。
再给 SQL/Python 和一张中间结果表；至少展示总行数、筛选后行数、分组后的前几行。
不要提前填最终数字；不确定列含义时先问我。
```

计算完请你自己抽查几行原数据：

- “第三高”是第三名的**金额值**还是第三个**对象**？并列时怎么处理？
- “会员数”通常要按账号去重；“交易笔数”通常按记录/交易 ID 计数。
- 金额是否有正负、币种、单位或小数精度？
- 日期范围是两端都包含，还是“到某天”为止不含次日？
- 排序前是否需要先按账号汇总？

### 6. Linux/服务器题：优先看配置与历史记录

有些题问系统版本、文件系统、主机名、服务地址或数据库配置。可以让 Agent 按题目给出最可能的文件和字段：

```text
这是授权练习中的 Linux 服务器检材。题目要确认：……
已知系统/镜像类型：……；现在能看到的文件：……。
请列出最可能的配置文件、日志或数据库位置，并写出只读查看方法；每种来源能证明什么？
如果建议启动虚拟机/容器，请先说可能改变哪些数据、怎么使用工作副本/快照。
```

**优先顺序**：先检查离线配置和日志；只有题目确实需要运行中的服务信息时，才考虑仿真。仿真用工作副本，记下哪些操作会写入日志或改变时间戳。密码、密钥、云凭证等只在授权检材内分析，不要复制到公开笔记或仓库。

### 7. 统计转账题：先分清“交易”和“转账记录”

链上一次交易可能包含多个代币转账记录。题目说“交易次数”，不能自动拿 Transfer 行数代替。

```text
这是授权练习导出的链上交易 CSV。
题目问：……；网络/链：……；代币合约：……；题目时区：……。
请先检查列名，说明哪些列对应交易哈希、日志序号、时间、发送方、接收方、原始金额和 decimals。
然后按题意说明该数的是交易哈希、Transfer 事件还是地址；写出筛选/去重/汇总步骤和中间表。
金额计算使用原始整数，最后才按 decimals 换算；所有无法从 CSV 确认的内容列为缺项。
```

**你要复核**：链/合约是不是题目指定的；时间是 UTC 还是题目本地时区；同一哈希下是否有多个日志；地址是否复制完整；小数精度是否正确。

### 8. 损坏文件和陌生格式：让 Agent 帮你找“正确解析方法”

运维赛 WP 的 FIT 文件题先确认文件来自 Garmin 设备，再参考厂商 SDK 修复/解析，并用 Python 库读取记录。这类题里，Agent 最适合帮你认格式、找官方文档、写解析代码；不要让它凭文件名猜内容。

```text
我有一个授权练习文件：……
文件大小：……；SHA-256：……；已知来源/扩展名：……；当前错误：……。
请先给出只读识别步骤（签名/元数据/结构），再建议厂商或格式维护方的官方工具/文档。
如果要写脚本，请先只读取副本、输出到新文件，保留原始哈希；给出字段解释和一条手工核对方法。
不要建议直接执行未知二进制文件。
```

### 9. APK/EXE/SO 题：一步一证据，不要直接“逆向出答案”

这类题通常先问哈希、包名、版本、导出函数或配置，再逐步进入代码分析。先让 Agent 列出基础信息和静态分析计划；运行程序只能在隔离、授权的练习环境中，并先说明可能影响。

```text
我有一个授权练习样本（APK/EXE/SO）：……，SHA-256 为……。
题目问：……。请先给不执行样本的静态检查顺序：文件类型/哈希/元数据/字符串/导入导出/配置。
针对每一步列出工具、只读命令和预期输出；不要猜结论。
我把输出贴回来后，请解释哪些字段直接支持答案、还缺什么证据。
```

## 六、让 Agent 写脚本时，要求它写得能检查

对 CSV、Excel、SQLite、文件清单可以用 Python/SQL 自动统计。提示词里应包括：

- 输入文件的格式、列名、编码、时间单位和时区；
- 只读输入，不覆盖原文件；结果写到单独目录；
- 缺列、坏行和空值如何报告，不要静默跳过；
- 输出中间数据，方便抽查；
- 给一小段样本和预期结果；
- 说明运行命令、依赖版本和两种复核办法。

```text
请根据我提供的列名和样例写 Python 脚本。
输入只读，输出写到新文件；不要联网，不要覆盖输入。
打印：读取行数、符合筛选行数、去重前后数量和最终结果；遇到坏行要报告行号。
先给代码和逐段解释，不要替我声称已经运行成功。

```

运行后把终端输出贴给 Agent 时，也要让它区分“程序输出了什么”和“这个输出能证明什么”。

## 七、一个完整的小例子：从登录题到可交答案

假设题目问：“某人离开期间，这台 Windows 笔记本有多少次成功登录？来源 IP 是什么？”

1. **你先给题目与条件**：指出离开日期、题目时区、需要统计“成功登录次数”和来源 IP。
2. **Agent 帮你列字段**：让它建议查哪些日志事件、账号/SID、成功/失败、时间、IP、工作站名。
3. **你导出相关日志**：保留 Record ID 和时间原值；不要只贴工具界面的一个总数。
4. **Agent 帮你过滤**：让它按时间窗和成功事件筛选，输出命中记录表与统计口径。
5. **你回到原始事件抽查**：检查首尾日期、时区、是否重复导入、目标账户是否一致。
6. **你提交简短答案**：写次数和 IP，备注证据范围；若多条记录出现多个 IP，就按题目要求列出或说明冲突，不要擅自挑一个。

## 八、题解、截图和 Agent 的常见坑

1. **WP 不是金标准。** 我参考的 2025 美亚杯团体赛复盘里，手机 Zoom 题和 TLS 1.3 套件题的答案标注前后不一致。遇到这种情况让 Agent 对照原始检材和官方标准复查，不要照抄。
2. **问清“到底数什么”。** 数行数、不同用户、交易哈希、Transfer 事件、文件数量可能得到不同结果。
3. **时间别混用。** 保留原始时间值，写清它是 Unix 秒、毫秒、UTC 还是 UTC+8，再做转换。
4. **一个痕迹不等于完整事实。** 某个应用目录存在不自动证明某人使用过；一个 IP 出现不自动证明某人操作；一次端口扫描不自动代表入侵成功。
5. **截图可读不等于信息完整。** 题目若问字段、哈希或精确时间，尽量回到原文件、日志或数据库。
6. **先看代码再运行脚本。** Agent 生成的脚本可能读错列、忽略坏行或覆盖文件；先检查，再在副本上跑。
7. **不能访问就明说。** 如果 Agent 没有实际读到文件，要求它先停在分析计划，不要编造“我检查后发现”。
8. **保护检材和隐私。** 只做授权练习；原件只读，分析副本；不把真实案件的个人数据、密码、私钥或云密钥上传或写进公开仓库。
