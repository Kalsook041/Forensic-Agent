# 用 Agent 解电子取证题：从题干到可复核答案

> 核心用法：让我帮你拆题、定位证据类型、写只读查询/脚本、解释输出和复核推理；证据本身仍要回到检材核对，不能把 Agent 的回答当成证据。

## 这份笔记依据什么

参考：[2025美亚杯 wp（团体赛）](https://www.digiforensics.cn/writeups/df-5odlmukg2q0k)，DigiForensics 社区投稿复盘。可见内容包括邮件材料、加密货币交易截图、手机数据和 Windows 笔记本痕迹。页面显示后续内容需登录，因此本笔记只归纳当前可见部分；它是选手复盘，不是官方标准答案。

## 先看题干属于哪一类

| 题干线索 | 题型 | 让 Agent 帮什么 | 你要提供/核对什么 |
|---|---|---|---|
| `.eml`、发件人、MIME、附件、Received、ARC/SPF/DKIM | 邮件取证 | 拆 MIME 结构、列附件、解析邮件头、解释认证字段和时间链 | 原始邮件或完整邮件头；核对原始字段，区分显示发件人和信封/认证信息 |
| PDF/JPG、EXIF、二维码、文件格式 | 文件与附件 | 写只读批量清单/解析脚本，解释签名、元数据和附件编码 | 原文件及哈希；对抽取结果检查文件大小、格式和来源邮件 |
| 钱包地址、代币、转账次数、金额、持有人、时间窗 | 链上数据统计 | 把题目转成筛选、去重、聚合、时间换算步骤；生成可复算的表格/脚本 | 链、代币合约、精确时间范围、原始交易记录和 token decimals |
| WhatsApp ID、IMEI、应用是否安装、聊天内容、电话号码 | 手机取证 | 根据系统/应用类型建议数据库、备份清单和字段；帮助写 SQL、整理证据表 | 授权检材副本、应用数据库及伴随文件；核对是否只是残留数据 |
| 登录账户、登录 IP、工作站名、账户删除、网络盘、软件记录 | Windows 主机取证 | 按时间窗筛 EVTX/注册表/应用痕迹，提取事件 ID、账户、IP 等字段 | 原始日志/解析导出、系统时区；区分登录成功/失败、账号和用户 SID |
| 法规、标准或基础概念选择题 | 理论题 | 先讲清概念，再对照官方规范/标准逐项排除 | 题目年份、适用地区/版本；要求给出可核对的权威来源 |
| 两台设备、邮件、聊天和转账串在一起 | 多源关联 | 先统一时区和实体，再建时间线，标记直接观察与推断 | 每条记录的原始时间、时区、设备/账号标识和来源位置 |

## 推荐的解题节奏

1. **先自己读题**：圈出对象、动作、时间范围、输出格式和时区。先做 3–5 分钟，记下自己猜的证据位置。
2. **让 Agent 拆题，先不求答案**：确认这题需要哪类检材、哪些字段、哪些条件；证据文件缺失时，先列缺项。
3. **一次只处理一个证据源**：先发文件清单、数据库 schema、邮件头或少量相关记录。不要一上来贴整盘镜像或整份隐私数据。
4. **把结论连接到原始证据**：要求指出文件路径、表名/行 ID、EVTX 记录号、包号/流号、交易哈希或原文行，并保留原始值。
5. **复核计算和解释**：自己在工具中重跑查询；复查时区、单位、去重口径、应用数据含义和替代解释。
6. **按题目要求作答，再复盘**：答案保持短，证据理由可回查；另记“本题学到的定位方法”，不要只记 flag/选项。

### 通用拆题提示词

```text
我在做一题经授权的电子取证练习。请先不要给最终答案。
请把题目拆成：
1. 题目要确认的事实和答案格式；
2. 题干里的对象、动作、时间范围、时区和单位；
3. 最可能的 3 个证据来源，按优先级排列，并说明每个来源能证明什么；
4. 我还需要提供哪些材料；
5. 最短的验证步骤，以及容易误判的地方。
如果你无法读取我提到的文件，请明确说出来，不要假装已经检查过。
题目：……
我目前找到的检材/文件：……
```

## 按题型提问

### 邮件、MIME 和发件人追踪

把完整原始邮件头或一封 `.eml` 的副本交给 Agent，先让它列出字段和值，再解释字段语义。可用提示词：

```text
只分析下面这份授权练习邮件，不要仅凭 From 字段判断真实发件人。
请列出 From、Return-Path、Message-ID、Authentication-Results、DKIM/SPF/ARC 结果和所有 Received 行；
说明 Received 链应如何排序，区分邮件内容中自报的信息与接收服务器记录。
对附件请列出文件名、Content-Type、Content-Disposition、Content-Transfer-Encoding、解码后大小和 SHA-256。
每个判断都引用具体原始字段；不能确认的写“无法从现有材料确认”。
邮件头/文件：……
```

注意：邮件里写了 `Received`、`From` 或认证结果，并不意味着每个字段都同样可信。截图或解析器摘要不能替代原始 `.eml`；附件抽取后要保留与原邮件的对应关系。

### 链上转账、金额和时间窗口

先确认链、合约地址、题目时间时区和“次数”到底指交易、Transfer 事件还是唯一交易哈希。金额先保留原始整数，最后再按 decimals 换算，避免浮点误差。

```text
根据下面的授权练习 CSV，先不要猜答案。
请说明字段映射，并按题目的链、代币合约和时间窗筛选；明确区分交易哈希数、Transfer 事件数和地址数。
按题意对地址/方向/金额分组，说明去重键、UTC 与题目时区换算及 decimals；给出中间表和可复算公式。
如果字段不足，先列出缺项，不要补造记录。
题目：……
CSV 列名与样例行：……
```

链上题常见失分点：把同一交易中的多个 Transfer 日志当成多笔独立交易；把钱包地址大小写、时区或代币精度处理错；只看截图却不保留交易哈希和原始记录。

### 手机应用、账号和聊天记录

先确认是 iOS 还是 Android、备份/镜像的类型，再从应用目录、数据库 schema、备份清单或取证工具导出结果定位。让 Agent 先解释表和字段，再生成只读 SQL；同时保留数据库主文件、WAL/journal 等伴随文件。

```text
这是经授权的手机取证练习副本。请先阅读下面的数据库 schema，不要推测缺失数据。
题目问：……
请指出可能相关的表/列，生成只读查询并解释每个条件；结果中保留主键、原始时间值和来源表。
再列出还需要哪项独立证据确认结论。请区分“应用曾存在/有残留数据”与“题目时间内确实使用”。
Schema/少量样例：……
```

### Windows 登录、账户和主机行为

把题目的时间窗和系统时区先写清楚，再让 Agent 根据日志导出表筛选。登录相关题目至少区分成功/失败、事件 ID、账户名/SID、Logon Type、来源 IP、工作站名和时间；不要只根据一条事件扩大推断。

```text
请只分析这份授权练习的 EVTX 导出 CSV。
题目时间窗：……；题目时区：……；要确认：……
请给出筛选条件和命中的记录号、事件 ID、原始时间、账户/SID、Logon Type、IP、WorkstationName；
区分直接观察与推断，并指出哪些字段为空或无法支持结论。先给可复核的查询/过滤条件，再给答案草稿。
```

### 需要脚本或批量统计时

先让 Agent 说明方案，再要求生成**只读输入、写入单独输出目录**的脚本。要求它列出依赖、运行命令、输出字段、异常处理和核对办法；原始检材不要作为脚本输出目标。样本行先核对结果，再扩大到整份导出数据。

```text
请写一个只读取 input 文件、把结果写到单独 output 目录的 Python 脚本。
不要联网、不要修改或覆盖输入。说明依赖、命令、输出列、时间与编码假设；
遇到缺列/坏行时报告行号，不要静默跳过。先用我给的小样本演示预期输出，并给我两种独立复核方法。
输入格式/样本：……
```

## 用 Agent 核验 WP，而不是照抄 WP

我检查的这份复盘可见内容中就有值得复查的标注：Zoom 安装题先标了一个选项，后面又说官方答案是另一个；TLS 1.3 套件题的高亮选项与随后写出的答案也不一致。对 TLS 套件，IETF [RFC 8446](https://www.rfc-editor.org/rfc/rfc8446.html) 列出的 TLS 1.3 名称包括 `TLS_AES_128_GCM_SHA256`、`TLS_AES_256_GCM_SHA384`、`TLS_CHACHA20_POLY1305_SHA256`；传统 `ECDHE_*_WITH_*` 名称不能不看版本就直接当成 TLS 1.3 套件。

看到题解与题干、原始材料或规范冲突时，可以这样问：

```text
请审查这段题解，不要默认作者答案正确。
把每题拆成：题干原文、题解给出的选项/答案、题解引用的证据、独立可核验的规范或字段、目前是否一致。
优先找答案标签冲突、时间/单位错误、字段含义混淆、统计口径不明和缺少证据定位的问题。
只把能由原始材料或权威来源支持的内容标为“已核实”；其余标“待核验”，并说明下一步需要什么证据。
题目与题解：……
```

**复核原则**：题解适合提示“去哪找”，不能替代原始检材；Agent 找到的规范说明也不能替代对本题版本、选项和原始数据的核验。

## 什么时候不要直接交给 Agent

- 还没说明题目口径、检材版本或时区，却要求它“猜一个答案”。
- 只有截图而题目实际需要原始邮件、EVTX、数据库或交易明细。
- 想让它把推断写成确定事实，或让它补齐缺失的日志/字段。
- 材料里包含真实案件中的个人信息、口令、密钥或未公开资料；没有明确授权时不要上传。练习时用比赛提供的副本和必要的脱敏片段。
- 脚本还没有看过就直接对原始镜像、备份或证据目录运行。
