# 同一检材添加新题（2026-10-17）

## 行为与范围

从已有案件的“添加新题”输入下一题，沿用同一个案件目录、检材来源和工作副本。先完整核验原件、副本、派生文件、工具输出与目录文件集合，再添加题目；失败时不切换题目、不追加工具步骤。不再次复制48 GiB，不直接解析原件。

范围：`src/forensic_agent/agent/loop.py`、`cli.py`、`gui.py`、`tools/runner.py`、`reports/writer.py`、`web/{app.js,index.html,app.css}`，`tests/test_next_question.py`、`test_gui.py`、`gui-client.test.mjs`、使用/验证文档及离线wheel/锁。

- 原题默认编号 `q0001`，新题分配 `q0002` 等编号；旧无编号案件兼容此默认值。
- `question_history` 保存前题题目、状态、计划、候选答案、历史候选、步骤编号、复用步骤编号及旧报告位置；新题答案和计划独立清空。证据库共用，已有候选答案不会自动成为新题答案。
- 新步骤及分析轮次携带题目编号；主报告显示当前题目的新增/规则复用步骤，并明确全部证据来自共用证据库。前题报告从原题目链接只读打开，不触发重新生成当前题目报告，也不混入当前题的人工指南。
- 已有等价工具请求不会再执行。规则模式仅复用状态为ok/partial且完整性通过的前题结果，保留partial与原输出，不自动推断答案；失败结果不会记作成功复用。模型引用仍逐字段、类型、值、来源核验。
- 每次显式分析有有限步数，整个案件的规划纠正、引用纠正分别仍最多一次；换题不重置预算、白名单、Shell或资源边界。原模型日志的追加规则、案件锁和报告备份失败保护保持。
- API只接受已有案件身份、新题文本与受支持模式；没有新增自由路径参数。历史报告按题目ID查找，拒绝遍历、未知题目及保存在案件之外的路径。
