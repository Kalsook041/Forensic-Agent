# 检材登记失败与 GUI 诊断修复（2026-10-17）

## 根因与修复

实际48 GiB分卷目录超过默认10 GiB副本上限。旧登记流程逐个复制后才累加总量，已复制约8 GiB才失败；Case.create虽持久化intake_failed案件，但调用方赋值未完成，CLI的case仍为None，未生成报告。GUI随后用“报告不可读”覆盖原始错误，使页面无法说明真正原因。分析工具和模型尚未开始，不能把这次失败归因于模型或工具解析结果。

- `evidence/store.py` 在复制第一份文件前检查已枚举文件总量和整个副本所需空间；错误包含总量、上限或可用空间。逐文件总量、磁盘余量及源文件变化检查继续保留，防止预检后输入增长或空间变化。
- `cli.py` 重载create已保存的失败案件，生成诊断报告；最后一次性输出原始错误、案件、状态及报告。报告读取/写入失败作为独立report_error保留，不能替换最初根因。
- `web/app.js` 在报告缺失时同时展示原始任务错误和诊断信息，隐藏旧报告操作，保留案件ID。失败不会显示为正常完成。
- 默认容量、来源/输出完整性、模型循环、工具白名单及运行额度均未提高。

对于分卷压缩包，先核对完整分卷并解包、确认解出的格式和所需解密步骤，再选择可处理的单个镜像或导出痕迹。10 GiB限制针对工作副本，不是压缩包下载大小；释放磁盘空间不会自动改变此限制。大镜像需要足够空间及操作员配置的案件容量，不能靠模型自行提升限额。
