# 审题计划与阶段报告验证（2026-10-18）

本轮基线 `aeaa86a`。模型首轮已有结构化审题，本轮将它以可读中文展示，并要求计划每步包含目的、工具/来源、范围、预期证据、完成条件和失败后的处理。仍采用原有六字段 TaskReview、1–3 步计划及原有模型调用流程；不增加独立预规划调用。

## 使用与边界

开始分析后，“阶段报告”随登记进度、模型审题/计划、工具执行和返回、分析结束逐段更新。页面沿用约 1 秒轮询；模型首轮返回之前不会出现审题文字，也不会在长工具执行中虚构结果。这是阶段流式展示，不是逐 token 输出。

最终报告仍将答案摘要放在最前，其后展示当前题的审题摘要与证据标准、分步操作计划。来源、字段、类型、原值和完整性仍经原校验流程；阶段预览标为待核验，不能代替最终答案。失败、不完整、中止保留已收到阶段，说明未完成核验。工具证据仅预览前三条，长文字有省略标记，完整工具证据仍保存在案件中。

每次 analysis_run 另有 `live-run-NNNN.jsonl` 追加阶段记录，运行间不会覆盖；辅助保存或推送失败只增加警告，保留主错误、状态和预算。GUI 最多保留 64 个阶段卡片、每卡正文 10000 字符；同一步执行卡被结果卡替换。前端使用 textContent，题目和工具中的 HTML 仅作为文字。

模型可能给出简短或不充分的计划。模板要求详细并不证明模型每次理解正确；本轮没有增加“语义完整性已验证”的承诺或额外反复纠正。8K 上下文、案件级规划/引用各一次纠正、工具白名单和禁止任意 Shell 均保持。
