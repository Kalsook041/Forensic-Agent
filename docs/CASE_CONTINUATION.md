# 继续同一案件

在工作台展开“历史案件”，找到原案件，点击“继续分析”。不用再次填写检材路径，也不用另建案件。继续使用该案件保存的题目；要调查另一道题，应单独登记新案件。

续跑前完整读取并核对原件、已有工作副本、派生文件和已记录工具输出的 SHA256。目录原件还核对登记文件集合。只有核验通过才继续；缺失或内容变化会停止并保留诊断。不会重新复制 48 GiB，也不会直接把原件交给解析器。

核验仍然需要读盘时间。目前每步工具和最终报告的完整性检查仍保留，因此本次改动解决的是重复副本和调查记录割裂；尚未交付跨步骤哈希缓存。

原案件编号、来源 ID、证据 ID 和步骤均保留，新步骤在原记录后追加。模型响应追加为新文件，首次响应和错误记录不覆盖。更新报告之前，将已有 `report.md` / `report.json` 保存到该案件的 `report-history/continuation-XXXX/`；原候选答案转入历史候选，后续答案继续经过来源、字段、类型、原值及完整性校验。

每次用户明确点击继续，最多追加配置中 `model.max_steps` 个工具步骤。规划纠正和引用纠正按整个案件分别最多一次，续跑不会重置；历史等价工具请求不会重新执行。规则模式仅会执行固定请求，若该请求已执行，就停止并说明重复；需要进一步规划时选择自动模式。

完整性失败、登记失败、未完成登记或仍有运行中步骤的案件不能继续。已清理工作副本、原件离线或原件集合变化时，需先处理原始问题。工作台会禁用不可续跑状态的按钮；实际续跑仍执行完整核验。案件有其他写入操作时，新的写入会被拒绝，操作结束后可再试。

命令行示例：

```powershell
.\.venv-offline\Scripts\python.exe -m forensic_agent --config .\config\default.toml analyze --case 'E:\ForensicWork\案件编号'
```

`--case` 与 `--evidence` 不能同时指定；续跑不接受 `--question`，防止混淆原案件题目。`--no-model` 选择规则模式。默认保留单个结果 JSON 输出；工作台使用 `--progress` 读取分阶段进度。

本轮验证、已知限制及可直接使用的复审/修复提示词见 [CASE_CONTINUATION_VALIDATION.md](CASE_CONTINUATION_VALIDATION.md)。
