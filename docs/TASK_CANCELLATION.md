# 工作台中止分析（2026-10-17）

任务运行时，在“分析结果”标题旁点击红色描边的“中止分析”。按钮不受输入表单禁用影响；点击后显示“正在中止”，确认任务进程树退出及诊断保存后显示“已中止”。不需要等待当前工具或模型的原超时。中止期间不能开始其他任务或退出服务，结束后可以开始新的任务。

只中止当前工作台任务，不删除原件、工作副本、工具输出和已有日志，不停止共享的Ollama服务。未完成的工作不是成功答案；取消报告明确跳过当前完整性复核并使当前候选失效。复制未完成的副本不能直接用于下一题；只有已完整登记的案件才可能继续，并仍须通过原有全量核验。续跑尚未进入新分析时取消，保留原有案件记录；单独报告重建被中止时也不改写原案件为取消。Markdown报告先写临时文件后替换，避免写入中止截断旧报告。

## 实现边界

- 认证、同源POST `/api/cancel` 只接受当前任务ID；旧ID、无效类型和缺失ID拒绝，不接受进程号或任意命令。重复请求幂等，已完成任务不强行标为取消。
- GUI启动代理在Windows Job分配成功前等待，分配失败不释放目标程序。取消覆盖启动前竞态、CLI、工具worker及其后代，输出排空和进程退出后才完成收尾；额外Job只负责GUI任务树生命周期，工具原有内存/CPU/进程数限额保持默认不变。
- 复制/哈希进度携带经过本地案件路径校验的案件目录，便于尚未完成登记时保留诊断。进程退出后才获取案件锁写取消记录；辅助诊断失败留日志，不伪称报告已保存。原错误和首次日志、案件级纠正预算不覆盖。
- 不新增模型/工具调用，不删除案件或临时副本，不开放Shell、任意可执行路径或工具白名单；Ollama的推理在客户端连接终止后的具体释放时间未单独验证。
